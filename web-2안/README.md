# web-2안 — 네모 카드 안

**1안은 `web/` 에 그대로 있다. 이 폴더는 지우지 않고 나란히 두고 고르는 2안이다.**

| 안 | 폴더 | 사건 하나를 그리는 방법 |
|---|---|---|
| 1안 | `web/` | 탭이 달린 **서류철(폴더)** |
| 2안 | `web-2안/` | **네모 카드**. 흰 바탕 위에 그 사건의 색 띠만 얹고, 진행 단계까지 카드에 그린다 |
| 3안 | `web-3안/` | 1안에서 **모양만 네모로**. 담는 내용은 1안과 같다 |

두 화면을 동시에 띄워 놓고 비교한다.

```bash
py web/serve.py 8765
py web-2안/serve.py 8766
```

## 2안이 1안과 다른 곳

친구가 깃허브에 올린 피그마 구현(`origin/main` 의 `web/`)에서 가져온 것이 ★ 다.

| 무엇 | 왜 |
|---|---|
| 폴더 모양 → 네모 카드 | 폴더 탭·비어져 나온 종이를 없애고 평범한 네모로 둔다. 사건의 색은 카드 맨 위 6px 띠로만 남긴다 — 상세 화면도 같은 띠 색을 써서 '그 카드를 열었다'가 그대로 보인다 |
| ★ 진행 단계를 목록 카드에 그린다 | 1안은 "접수 단계"라는 한 줄이었다. 어디까지 왔고 무엇이 남았는지는 글자보다 단계 줄이 먼저 읽힌다 |
| ★ 접는 것 없이 다 보인다 | 유형·기준일·기간·자료 수·확인 필요 수·다음 행동을 처음부터 다 둔다. **손가락으로 쓰는 화면에는 마우스 올림이 없다** (이 지적을 받아 1안·3안도 같이 펴 두었다) |
| ★ 확인 필요 · 확보 자료를 알약으로 | 숫자 두 개를 문장에 섞지 않고 색이 있는 알약으로 떼어 놓는다. 확인 필요는 붉은색이다 |
| ★ 머리말에도 「+ 새 사건 등록」 | 사건이 늘면 목록 끝의 점선 카드가 화면 밖으로 내려간다. 입구를 위에도 둔다(1안은 중복이라 뺐던 것 — **여기서 의견이 갈릴 수 있다**) |
| 기한(D-day)은 그대로 항상 보임 | 1안에서 정한 것을 지킨다. 목록 카드·상세 머리말 모두 같은 붉은 알약(`due-pill`)으로 맨 위에 둔다 |
| 새 사건 등록에서 서류철 껍데기를 벗김 | 폴더가 없어졌으므로 '빈 서류철' 비유도 뺀다. 카드 두 장만 쌓는다 |

`assets/` 의 로고·아이콘·토큰, `data/cases.js`, 나머지 화면(시작 · 로그인 · 회원가입 · 타임라인 · 인물 · 주장 대조)은 **1안과 같다.** 로고를 만드는 `tools/make_logo.py` 는 1안 폴더에만 둔다.

---

아래는 1안 README에서 2안에 맞게 고친 설명이다.

피그마 [타래 UI](https://www.figma.com/design/Y5ZZ1AyURJLKvR48kMVas4/%ED%83%80%EB%9E%98) 세 화면을 옮긴 정적 화면이다. 빌드 도구 없이 HTML · CSS · 바닐라 JS만 쓴다.

| 파일 | 피그마 프레임 | 하는 일 |
|---|---|---|
| `index.html` | — | 시작 화면. 실 그림 + 로그인·회원가입 (`assets/landing.css` · `assets/landing.js`) |
| `login.html` · `signup.html` | — | 로그인 · 회원가입 폼 (`assets/auth.css` · `assets/auth.js`) |
| `cases.html` | 01 내 사건 | 사건 카드 목록. 카드를 누르면 사건 상세로 간다 |
| `new.html` | 02 새 사건 등록 | 사건 유형 선택과 자료 올리기를 한 화면에서 |
| `case.html?id=…` | 03 사건 상세 · 타임라인 | 타임라인 · 인물 · 주장 대조 · 다음 행동 · 확인이 필요해요 |

앱 안쪽 화면의 브랜드(**타래**)를 누르면 시작 화면으로 나가고, 옆의 **내 사건**이 목록으로 간다.

## 실행

`data/cases.js`와 스크립트를 상대 경로로 읽으므로 로컬 서버로 연다.

```bash
python web-2안/serve.py 8766
```

<http://localhost:8766>

`python -m http.server` 대신 이 스크립트를 쓴다. 기본 서버는 캐시 헤더를 주지 않아서
**브라우저가 고친 HTML·CSS 를 안 받아 오고 옛 화면을 계속 보여 준다.** `serve.py` 는 `no-store` 를 붙인다.
(윈도우 깃배쉬에서는 `python` 이 스토어 스텁이라 `py web-2안/serve.py` 로 실행한다.)

## 데이터는 엔진에서만 온다

화면은 `data/cases.js`(`window.TARAE_CASES`)만 읽는다. 이 파일은 손으로 고치지 않고 엔진 출력으로 만든다.

```bash
cd action-engine
uv run python tools/export_web.py
```

이 스크립트는 **1안(`web/data/cases.js`)에만 쓴다.** 다시 만든 뒤에는 `cp web/data/cases.js web-2안/data/cases.js` 로 이 폴더에도 옮긴다(시안을 고르면 한 쪽만 남으므로 그때까지만 손으로 맞춘다).

`research-engine` 픽스처 → `build_card()` → 화면용 값. 엔진이나 픽스처를 고치고 다시 만들지 않으면 `test_커밋된_화면_데이터가_엔진_출력과_같다`가 실패한다.

- **다음 행동 카드의 무엇을·어디에·언제까지**는 지식베이스(`documents.json` · `deadlines.json`)에 있을 때만 채운다. 없으면 피그마 시안의 예시 문구 대신 "절차는 아직 확인 중"으로 둔다.
- 예시 사건 셋 중 **고소 사건(수사중지)** 만 절차가 채워진다(이의제기 기한 D-5). 나머지 둘은 다음 행동의 절차가 검수 전이라 비어 있는 것이 정상이다.
- 액션 이름(`ACT-신규정보제출` → "새로 확인된 정보를 수사기관에 제출")은 `export_web.py`의 `ACTION_LABELS`에 있다. 절차 문구가 아니라 행동의 이름만 적는다.

## 시안과 다른 곳

| 항목 | 이유 |
|---|---|
| 새 사건 등록의 자료 목록이 비어서 시작 | 시안은 자료 4개를 올린 상태를 그렸다. 실제 첫 화면은 빈 목록이다 |
| "정리 시작하기"가 예시 사건으로 이동 | 서버가 없어 올린 파일을 실제로 정리하지 않는다 |
| 인물 · 관계는 나무 모양 | 목록으로 늘어놓으면 누가 어디에 걸려 있는지 안 보인다. 사건을 뿌리로 두고 사람·기관·번호로 갈래를 친다. 엔진이 합치지 못한 '같은 대상일 수 있음'은 점선 상자로 붙인다 |
| 오른쪽 열은 탭마다 다름 | 다음 행동·확인이 필요해요는 타임라인에서만 쓴다. 인물·주장 탭에서는 그 화면에서 실제로 쓰는 것(자료 · 전문가 질문)만 둔다 |
| 인물 · 관계 / 주장 대조 탭을 엔진 데이터로 채움 | 피그마에 설계가 없지만 엔진이 이미 주는 값이다. 인물은 `timeline.entities`(역할 · 합치지 못한 '같은 대상일 수 있음' 링크까지), 주장 대조는 `analysis.slot_statuses` + 같은 항목의 `claims` — **기록 자료와 사람의 말을 구분해서** 나란히 놓는다 |
| 타임라인 한 줄은 날짜 · 점 · 짧은 제목 · 자세히 | 줄에 뱃지·출처를 다 붙이면 읽히지 않는다. 짧은 제목은 **원문에서 덜어내기만 한다** — 왼쪽 칸에 날짜가 있으니 앞머리 날짜를 떼고, 여러 문장이면 첫 문장만 남긴다(`_short_title`). 요약 문구를 새로 지어내지 않는다 |
| 「자세히」에 원문과 출처 | 상태(확인 완료 / 주장·미확인 / 불일치 / 날짜 확인 필요), 원문 전체, 어느 자료 몇 줄에서 왔는지와 인용문. 원본 사진 띄우기는 아직 연결되지 않았다고 적는다 |
| 타임라인 점 색 | 확인완료는 진회색, 확인되지 않은 것은 노랑, 어긋난 것은 빨강 |
| 타임라인에 "날짜 확인 필요" 배지 | 엔진이 날짜를 추정한 사건(`needs_confirmation`)을 알려준다 |
| 카드 선택 테두리는 마우스 올림·키보드 포커스에서 | 시안의 첫 카드 보라 테두리는 선택 상태를 보여준 것이다 |
| 내 사건 목록은 네모 카드 | 사건 하나가 카드 한 장이다. 유형 · 기준일 · 제목 · 기간 · 자료 수 · 진행 단계 · 확인 필요 수 · 다음 행동을 접지 않고 다 보여준다. 카드 맨 위 6px 띠가 그 사건의 색이다 |
| 카드의 D-day는 맨 위 오른쪽에 | 기한은 놓치면 되돌릴 수 없어서 스크롤·펼치기 뒤에 숨기지 않는다 |
| 사건 상세의 머리말도 같은 네모 카드 | 목록에서 고른 카드를 펼친 화면이라는 걸 보이게 한다. **목록에서 그 사건이 가졌던 띠 색을 그대로 쓴다**(`toneOf`) |
| 새 사건 등록은 점선 네모 카드 | 목록 끝의 점선 카드(사건 등록)가 그대로 이어진다 |
| 사건 상세는 접을 것만 접는다 | 타임라인·인물·주장은 스크롤 없이 그대로 펼친다(자료가 많은 사건은 페이지가 길어진다). 대신 자료 목록·행동 설명은 팝업, 확인이 필요해요는 접어 둔다 |
| 「사진 찍기」가 카메라를 연다 | 노트북에서는 웹캠 미리보기를 띄워 찍고(`getUserMedia`), 휴대폰에서는 기본 카메라를 쓴다(`capture`). 권한을 막거나 카메라가 없으면 파일 선택으로 물러난다 |
| 「기억나는 내용을 직접 적기」가 동작 | 자료가 없어도 적어 둘 수 있다. '직접 적음'으로 들어가고 기록 자료와 구분해서 표시한다 |
| 자료 추가·직접 입력이 화면 안에서 끝남 | 「자료 추가하기」는 파일 창을 열고, 「기억나는 일을 직접 추가」는 입력 창을 연다. 서버가 없어 **이 화면에만** 더해지고 저장되지 않는다 — 그 사실을 창 안에 적는다. 직접 적은 줄은 '내가 적음'으로 들어가고 시간 순서에 맞춰 끼워진다 |
| 「전문가에게 물어볼 질문 만들기」가 실제로 동작 | 화면에 올라온 것(사건 요약 · 확인이 필요한 것 · 다음 행동)에서 질문지를 뽑아 팝업에 띄우고 복사할 수 있게 한다. 질문 틀은 갈래마다 정해 두고 내용은 엔진이 올린 문장을 그대로 넣는다. 법률 자문이 아니라 '물어볼 거리'라고 적는다 |
| 상단바에 메뉴 · 프로필 · 도움말 | 삼단 메뉴는 내 사건·새 사건 등록·자료 추가하기·도움말, 프로필은 내 정보·로그아웃. 도움말은 이 서비스가 무엇을 하고 **무엇을 하지 않는지**를 일상어로 적은 창이다 |
| 자료를 늘어놓지 않고 버튼 뒤에 둠 | 파일 이름이 화면 위쪽을 차지할 이유가 없다. 「+ 자료 추가하기」와 「첨부한 자료 N」 두 버튼을 오른쪽 열 맨 위에 두고, 목록은 팝업으로 연다 |
| 진행 단계 이름은 사건 유형마다 다름 | 엔진 `Stage` 는 여섯 가지(발생·송금·신고·접수·수사·결과)로 유형을 가리지 않는다. 수사중지 사건이 '결과'로 끝나면 사건이 끝난 줄 안다 — 실제로는 **중지**이고 뒤에 되살릴 길이 남아 있다. `export_web.py` 의 `STAGE_TRACKS` 가 화면 이름만 바꾼다(실종: 발생·신고·수사·**중지**·재수사 / 수사중지: 고소·접수·수사·**중지**·재개). 엔진 코드는 건드리지 않는다 |
| 진행 단계는 보라 선 + 현재 마디가 빛남 | 어디까지 왔는지를 색 대비로 먼저 읽히게 한다. 흰 카드 위라 브랜드 색을 쓰고, 남은 구간은 흐린 회색 |
| 1024px 이하에서 한 열로 접힘 | 시안은 1440px 데스크톱. 1차 사용자가 휴대폰을 쓴다 |

## 로고

`assets/logo-original.png` 가 손으로 그린 원본(흰 배경 · 검은 그림)이다. 화면에 쓰는 두 파일은 여기서 만든다.

| 파일 | 어디에 |
|---|---|
| `assets/logo.png` | 밝은 화면 — 앱 상단바, 파비콘 |
| `assets/logo-light.png` | 어두운 화면 — 시작 · 로그인 · 회원가입. **선만 흰색으로 남기고 줄무늬는 뚫는다** — 원판을 칠하면 어두운 바탕 위에서 덩어리로 보인다 |

만드는 법은 1안 폴더의 `web/tools/make_logo.py` 에 있다. 바깥 흰 배경만 투명하게 하고(원 안쪽 흰 줄무늬는 그림의 일부라 남긴다) 검은 부분에 색을 올린다. 원본을 다시 그리면 이 스크립트를 다시 돌린다.

```bash
py web/tools/make_logo.py
```

글꼴은 두 가지다. 본문은 **IBM Plex Sans KR**(`--font`), 이름 '타래'만 **Gugi**(`--font-brand`)를 쓴다 — 붓 느낌이라 실타래라는 이름과 맞고, 굵기가 하나뿐이라 400 으로 쓴다. 바꾸려면 `tokens.css` 의 `--font-brand` 한 줄과 각 HTML 의 구글 폰트 주소만 고치면 된다.

토큰(`assets/tokens.css`)은 피그마 변수 이름과 1:1이다(`bg/canvas` → `--bg-canvas`). 아이콘은 피그마 에셋 원본(`assets/icons/`)이다.
