# 시험자료

엔진이 실제로 돌아가는지 보려고 만든 가상 사건이다. **인물·사건·서류는 전부 지어낸 것**이고,
문구만 실제 서식(경찰수사규칙 별지 서식)의 항목 이름을 따랐다.

각 폴더는 `research-engine` 이 받는 입력이다 — OCR 이 서류를 읽었을 때 나오는 모양 그대로다.
카드 내용을 손으로 쓰지 않는다. 서류를 넣고 엔진이 무엇을 만드는지 보는 것이 목적이다.

## 돌리는 법

```bash
cd research-engine
uv run research-engine run ../시험자료/<폴더>/case.json --out ../시험자료/<폴더>/out.json
```

나온 `out.json` 을 `action-engine` 이 읽는다.

```bash
cd action-engine
uv run python -c "
import json
from action_engine import build_card
from action_engine.draft import build_draft
r = json.load(open('../시험자료/<폴더>/out.json', encoding='utf-8'))
c = build_card(r)
print(c.st.code, c.next_action.action, c.checklist.form_name)
"
```

## 무엇을 보려고 만들었나

| 폴더 | 보려는 것 | 나온 것 |
|---|---|---|
| `불송치-이의신청/` | 불송치 결정을 받은 사건. ST-301 · 별지 제125호 · 기한 없는 불복 경로 | **버그 2건**을 찾았다 (아래) |
| `결정내용-없음/` | 통지서가 없어 결정을 모르는 사건 | 단계 추정(ST-102)으로 떨어진다 |
| `자료-어긋남/` | 고소장과 진술서의 날짜가 다르고, 판독이 흐린 줄이 있는 사건 | **버그 2건** (아래 3·4) |
| `흐린-통지서/` | 결정 부분만 번져 무슨 결정인지 모르는 통지서 | **버그 1건** (아래 5) |
| `규칙별/` | 규칙표 13줄을 규칙마다 사건 하나로 발화시키는 시험 (0~12번) | 13 / 13 발화 — 처음 9 / 13 에서 막힌 원인 셋을 고쳤다 (`규칙별/README.md`) |

## 여기서 찾은 것

1. **`불송치(혐의없음)` 을 검찰 불기소로 판정했다.** '혐의없음'은 불송치의 이유이지 검찰의
   처분이 아닌데, 판정표가 '혐의없음'을 먼저 집었다. 경찰에 낼 이의신청 대신 검찰 항고를
   안내하게 된다 — 제출처도 서식도 전부 달라진다.
   → `mapping.DECISION_TABLE` 의 불기소 줄에 `불송치` 를 제외 조건으로 넣었다.

2. **기한이 없는 불복 경로는 한 번도 안내되지 않았다.** 불송치 이의신청(형사소송법
   제245조의7)은 법정 기한이 없다. 그런데 불복 규칙이 '기한이 급할 때'만 발화해서,
   급해질 수가 없는 경로는 영영 다음 행동이 되지 못했다. 통지를 받고 가장 먼저 열리는
   길인데도 그랬다.
   → 규칙표에 '불복할 수 있는 결정을 받은 상태'(ST-301·302·303) 줄을 넣었다.

3. **현금을 직접 건넨 사건이 통째로 사라졌다.** 송금·이체·입금만 보고 있어서
   '현금 400만원을 건넸습니다' 는 이벤트도 주장도 만들어지지 않았다. 피해자가 적은
   사건의 핵심이 조용히 없어지고, 그러니 두 자료의 날짜 차이도 비교될 일이 없었다.
   → `extract/events.py` · `extract/claims.py` 에 금액이 앞에 오는 '건네·지급·전달'을 더했다.
   금액이 있을 때만 잡는다 — '서류를 건넸습니다'까지 끌어오면 안 된다.

4. **유형이 요구하지 않는 항목은 영어 키가 그대로 샜다.** 수사중지 사건 정의에
   `transfer_time` 이 없어서 화면에 `transfer_time: 자료 사이에 차이가...` 로 나왔다.
   → `SLOT_DEFAULT_LABELS` 를 깔아 어떤 항목이든 한글 이름이 나오게 했다.

5. **적어 내는 서류가 아닌 것에도 초안을 만들었다.** `ACT-단계확인` 의 '형사사법포털
   사건조회'는 접속해서 조회하는 절차인데 사건 경위 초안을 내놓았다. 없는 서류를
   쓰려고 앉게 된다.
   → 지식베이스에 `생성가능` 으로 적힌 서류가 있을 때만 초안을 만든다.

1·2·5 는 `action-engine` 테스트로, 3·4 는 `research-engine` 테스트로 굳혔다.

## 확인했지만 문제가 아니었던 것

- **모순 감지는 정상이다.** 7. 9. / 7. 11. 차이를 잡아 '차이가 있어 보이지만 판단 근거가
  부족합니다 (모순 점수 0.68 < 기준 0.70)' 로 알린다. 단정하지 않고 되묻는 것이 설계다.
- **`ST-UNKNOWN` 경로도 정상이다.** 결정을 읽을 수 없으면 단계를 찍지 않고 '지금 어느
  단계인지 확인' 을 먼저 안내한다.

## 아직 못 본 것

- **공소시효(TIM-021)는 한 번도 계산되지 않았다.** 죄명을 엔진이 아직 뽑지 않아서
  언제나 '죄명 정보가 없어 계산할 수 없습니다' 로 떨어진다. 죄명 추출이 생겨야 열린다.
- **증거보존 기한(TIM-031)** 도 기산일(통신 발생일)을 채우는 경로가 없어 계산되지 않는다.
- 타임라인 제목이 단계 이름을 쓴다 — 현금을 건넨 일도 '4,000,000원 송금' 으로 나온다.
  단계 이름이라 틀린 말은 아니지만, 사용자가 쓰지 않은 낱말이다. 기능 1 쪽 설계 선택이라
  손대지 않았다.
